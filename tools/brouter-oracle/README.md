# BRouter test oracle

`app/packages/brouter_dart` has to behave exactly like upstream BRouter. This
directory is the reference: it runs the real **BRouter 1.7.10** against two
committed `.rd5` tiles, records a corpus of routing requests with their full
responses, and dumps rd5 micro-caches and profile evaluations as JSON through the
upstream Java classes. Profiles are used **in place** from `brouter/profiles/`,
so the oracle and the deployed server cannot drift apart.

## Parity levels

| Level | What has to match | Tool |
|---|---|---|
| **L1** | byte-identical `util`/`codec` round trips and rd5 decoding | `dump/run_dump.sh dump-microcache` |
| **L2** | bit-identical profile evaluation | `dump/run_dump.sh eval-profile`, over the tag corpus `way-tags` builds |
| **L3** | identical coordinates, length, ascent, messages and voice hints over 224 routing cases | `gen_corpus.py` / `run_corpus.py` / `check_corpus.py` plus `corpus/` |

The golden tests in `app/packages/brouter_dart/test/` read `corpus/` and `dump/samples/` directly.

## Quick start

Java 17, Python 3 (stdlib only), `curl`, `unzip` — no Docker, no Gradle, no pip
packages. `common.sh` uses `JAVA_HOME`, else mise's `java@temurin-17`, else `java`.

```sh
cd tools/brouter-oracle
./fetch.sh          # ~7 MB: the upstream release zip. The rd5 tiles are
                    # committed and only copied into .cache/segments4, so
                    # ./fetch.sh --tiles-only touches no network at all (CI).
./serve.sh          # RouteServer on 127.0.0.1:17777
python3 check_corpus.py
./stop.sh
```

`serve.sh` refuses to start if something already answers on port 17777, so a stale
server cannot record against the wrong segments (`BROUTER_ORACLE_PORT` moves it).

## Exit codes

| Script | Code | Meaning |
|---|---|---|
| `fetch.sh` | 0 | tiles staged and verified against `tiles.sha256` |
| | 1 | a tile in `tiles.txt` is neither committed nor downloadable |
| | 3 | checksum mismatch — a committed fixture or the staged copy does not match `tiles.sha256` |
| `check_corpus.py` | 0 | all 224 cases reproduce |
| | 1 | at least one mismatch; per-case diff in `.cache/check-diff.txt` |

On 1 and 3, `fetch.sh` moves the tiles into `.cache/segments4-bad/` so nothing
can compare against the wrong bytes. CI runs it bare, so a failure is a red job.

## Layout

```
common.sh fetch.sh serve.sh stop.sh   paths, the pinned version, the server
tiles/ tiles.txt tiles.sha256         the committed rd5 fixtures + provenance
gen_corpus.py run_corpus.py           generate and record -> corpus/
check_corpus.py oracle_common.py      replay and compare
dump/Dump.java dump/run_dump.sh       the Java dump tool on the upstream API
dump/samples/  .cache/                recorded JSON; downloads and builds (ignored)
```

## The pinned upstream

`brouter/UPSTREAM_VERSION` is the single source of truth (`v1.7.10`). `fetch.sh`
resolves `brouter-1.7.10.zip` through the GitHub releases API and checks its
sha256; the jar's `Main-Class` is `btools.server.BRouter`, so `serve.sh` names
`RouteServer` explicitly:

```sh
java -Xmx256M -DmaxRunningTime=0 \
  -cp .cache/zip/brouter-1.7.10/brouter-1.7.10-all.jar \
  btools.server.RouteServer \
  .cache/segments4 ../../brouter/profiles .cache/customprofiles 17777 4
```

Three things in 1.7.10 are not deterministic, and the harness closes all three:
the 60 s routing timeout (`-DmaxRunningTime=0`), round trips without a start
bearing (every such case passes an explicit `direction`) and response gzip (all
requests send `Accept-Encoding: identity`).

## The corpus

224 cases, 112 per region, generated by `gen_corpus.py` from seed `20260912`.
Anchor points are sampled from the geometry of fixed backbone routes, so every
waypoint sits on the real road network; a candidate is kept only if it routes.

| Kind | Cases | What it exercises |
|---|---:|---|
| `pair` | 120 | 6 profiles × `alternativeidx` 0–3 |
| `triple` | 40 | a via point, cycling profiles and alternatives |
| `nogo` | 24 | `nogos=<lon>,<lat>,<radius-m>`, radii 120/200/350 m |
| `roundtrip` | 16 | `engineMode=4` with `roundTripDistance`, `direction`, `roundTripPoints=5` |
| `voice` | 24 | turn instructions on: `timode=2` (what the app sends) and `timode=1`, the `voicehints` block compared with the rest of the body |

`corpus/index.json` records per case `status`, `track_length`, `filtered_ascend`,
`plain_ascend`, `cost`, `coordinates`, `messages`, `bytes` and the body `sha256`,
all compared exactly; the response bodies (5.0 MB) are committed.

Round-trip parameters are the real ones in `RoutingParamCollector.setParams()`:
`roundTripDistance` is the **radius in metres** to the generated circle points,
not the total length; there is no `roundTripStartDirection`.

## The tiles, and re-recording

`tiles/W20_N30.rd5` (Madeira) and `W25_N60.rd5` (SW Iceland) are committed, pinned
by `tiles.sha256`. brouter.de rebuilds `segments4` nightly, so everything recorded
from them is valid only for those checksums; `tiles/README.md` has the snapshot
date and the ODbL attribution.

To bump the snapshot — a deliberate act, never to turn a red test green:

```sh
rm -rf .cache/segments4 && rm -f tiles/*.rd5
./fetch.sh --tiles-only || true      # falls back to the upstream mirror, exits 3
mv .cache/segments4-bad/*.rd5 tiles/ # confirming you mean to re-bind
(cd tiles && sha256sum *.rd5) > tiles.sha256
./fetch.sh --tiles-only              # must be green now
# update the sizes and index timestamp in tiles.txt and tiles/README.md
./serve.sh && python3 gen_corpus.py && python3 run_corpus.py && python3 check_corpus.py && ./stop.sh
# re-record the brouter_dart mapaccess vectors (see that package's README)
```

Commit the tiles, `tiles.sha256`, `tiles.txt`, `corpus/` and the vectors in **one** commit.

## The Java dump tool

`dump/run_dump.sh <command>` compiles `dump/Dump.java` into `.cache/` on first use;
a bare tile name resolves in `.cache/segments4`, a profile in `brouter/profiles`.

| Command | Produces |
|---|---|
| `dump-microcache <tile> <lon> <lat> [--geometry] [--profile p] [--limit n]` | the decoded micro-cache: node ids, `ilon`/`ilat`, `selev`, description bitmaps, links, raw geometry bytes. Without `--profile` it is the raw L1 target; with one, inaccessible ways drop out as in the router |
| `microcache-bytes` / `microcache-listing` | the raw encoded micro-cache, and the listing the Dart decoder must reproduce |
| `codec-vectors <out-dir>` | JSON test vectors for `util` and `codec` |
| `osmfile-index <tile>` | header, file index, per-cell sizes and crcs |
| `nodes-cache-walk <bbox> [--steps n] [--profile p]` | a `NodesCache` walk mirroring `RoutingEngine` |
| `way-tags <tile> [--kind node]` | every distinct way (or node) tag string of a tile, sorted |
| `eval-profile <profile> <tagsfile> [--bits] [--compact] [--encode] [--context node]` | every cost variable a `.brf` produces per tag set, both directions; `--bits` prints `Float.floatToIntBits`, `--compact` de-duplicates the vectors |
| `math-vectors` / `core-vectors <out>` | JVM float parse/format/arith, `exp`, `DecimalFormat` and `Double.toString` vectors for `jfloat.dart` / `jmath.dart` |

Two limits of the upstream API matter: `BExpressionContext` cannot enumerate its
variable table, so `eval-profile` reports the 20 built-in way variables plus
every name the `.brf` `assign`s; and `MicroCache` exposes node **bytes**, not
objects, so the dump reports the raw bytes and the decoded view.

## Known limits

- The two tiles are islands with a modest, mostly paved network: no motorways,
  no ferries, little of what an Alpine tile throws at `mtb` or `gravel`.
- `check_corpus.py` counts `messages` rather than comparing them field by field,
  but the body `sha256` covers them exactly.
