# App icon

`icon.svg` is the source. Everything else is generated from it.

The mark is a rounded square with a route glyph: three waypoint circles — a
start, a via point and a finish — joined by two gently bowed route strokes,
which read as a V. No text, and no reference to any partner brand (Strava's
guidelines forbid their name in an app icon).

## The colours

The icon is the app's volt accent (`AccentPreset.volt` in `lib/app/theme.dart`),
in two variants, and the launch screen is the same two:

| | tile | glyph |
| --- | --- | --- |
| light | `#3F7A00` (`volt.light`) | white |
| dark | `#C8F542` (`volt.dark`) | `#0E1115`, the app's ink |
| monochrome / tinted | — | the glyph alone, transparent ring holes |

They do not follow the accent the rider picks in Settings → Appearance: a
launcher icon that changed colour would not be recognisable.

| file | what it is |
| --- | --- |
| `icon.svg` | the light icon, full bleed and opaque (both stores reject transparency, and both platforms apply their own corner mask) |
| `icon_dark.svg` | the dark icon, same geometry |
| `icon_foreground.svg` | the adaptive-icon foreground: the white glyph at 90 %, ring holes in the light tile colour |
| `icon_foreground_dark.svg` | its dark twin — not used on the phone, only by the site's maskable icon and the iOS dark launch image, both over a `#C8F542` field |
| `icon_monochrome.svg` | the Android 13 themed-icon layer: the glyph at 90 %, ring holes punched out by a mask, because the launcher recolours the alpha channel |
| `icon_tinted.svg` | the same glyph full bleed, for the iOS tinted appearance and the launch images |

`icon_foreground.svg` and `icon_monochrome.svg` scale the glyph to 90 % because
`ic_launcher.xml` insets those layers by a further 16 %; together that keeps the
mark inside the adaptive icon's safe zone on every mask shape.

## Regenerating

```sh
cd app/assets/icon
rsvg-convert -w 1024 -h 1024 icon.svg            -o icon.png
rsvg-convert -w 1024 -h 1024 icon_foreground.svg -o icon_foreground.png
rsvg-convert -w 1024 -h 1024 icon_monochrome.svg -o icon_monochrome.png
cd ../.. && dart run flutter_launcher_icons
```

Any SVG rasteriser does; `magick -background none icon.svg -resize 1024x1024
icon.png` or Pillow produce the same thing. `flutter_launcher_icons` is
configured in `pubspec.yaml` and writes:

* `android/app/src/main/res/mipmap-*/ic_launcher.png` (legacy launcher icon),
* `android/app/src/main/res/drawable-*/ic_launcher_foreground.png` and
  `ic_launcher_monochrome.png`, plus `mipmap-anydpi-v26/ic_launcher.xml` with
  its `<foreground>` and `<monochrome>` layers and the `ic_launcher_background`
  colour in `values/colors.xml` (the adaptive icon),
* `ios/Runner/Assets.xcassets/AppIcon.appiconset/*` with the alpha channel
  removed, which the App Store requires.

### The iOS appearance variants

iOS 18 draws a dark and a tinted icon beside the light one. They are not
generated by the plugin, and **`dart run flutter_launcher_icons` rewrites
`AppIcon.appiconset/Contents.json` from its own template**, so after every run
re-add the two `appearances` entries (`luminosity` → `dark` and `tinted`,
`"idiom": "universal"`, `"platform": "ios"`, `"size": "1024x1024"`) next to the
generated ones, and regenerate their images:

```sh
AI=app/ios/Runner/Assets.xcassets/AppIcon.appiconset
rsvg-convert -w 1024 -h 1024 app/assets/icon/icon_dark.svg   -o $AI/Icon-App-1024x1024@1x-dark.png
rsvg-convert -w 1024 -h 1024 app/assets/icon/icon_tinted.svg -o $AI/Icon-App-1024x1024@1x-tinted.png
```

The tinted image keeps its alpha channel on purpose: iOS builds the tint from
it. Only the marketing icon has to be opaque.

## The launch screen

The splash is the icon filling the screen: the tile colour with the glyph
centred on it, light or dark with the system theme.

* **Android** — `res/values/colors.xml` and `res/values-night/colors.xml` hold
  `velorki_splash_background` and `velorki_splash_glyph`;
  `res/drawable/splash_icon.xml` is the glyph as a vector drawable, tinted from
  those two colours — the ring holes are filled with the background, painted
  over the route strokes, exactly as in `icon.svg`, because the route ends in a
  round cap at the centre of each ring.
  `res/drawable{,-v21}/launch_background.xml` (before Android 12) and
  `windowSplashScreenBackground` / `windowSplashScreenAnimatedIcon` in
  `res/values{,-night}/styles.xml` (Android 12+) both use them, so there is one
  copy of the artwork and night mode is a colour swap. No splash package is
  used.
* **iOS** — `Base.lproj/LaunchScreen.storyboard` centres the `LaunchImage`
  image set on the `LaunchBackground` named colour; both carry an Any and a
  Dark appearance. Regenerate the images (240 pt at 1×, 2×, 3×; the dark ones
  are the same alpha filled with `#0E1115`):

```sh
LI=app/ios/Runner/Assets.xcassets/LaunchImage.imageset
rsvg-convert -w 240 -h 240 app/assets/icon/icon_tinted.svg -o $LI/LaunchImage.png
rsvg-convert -w 480 -h 480 app/assets/icon/icon_tinted.svg -o $LI/LaunchImage@2x.png
rsvg-convert -w 720 -h 720 app/assets/icon/icon_tinted.svg -o $LI/LaunchImage@3x.png
for f in LaunchImage LaunchImage@2x LaunchImage@3x; do
  size=$(magick $LI/$f.png -format '%wx%h' info:)
  magick $LI/$f.png -alpha extract /tmp/glyph-alpha.png
  magick -size $size xc:'#0E1115' /tmp/glyph-alpha.png -alpha off \
    -compose copy_opacity -composite $LI/$f-dark.png
done
```

## Store listings

Both stores want the same square artwork as a separate upload — the icon in
the app bundle is not reused:

* Google Play → Store listing → App icon: **512 × 512** PNG, 32-bit, no
  transparency. `rsvg-convert -w 512 -h 512 icon.svg -o velorki-play-512.png`.
* App Store Connect → App information → App icon: **1024 × 1024** PNG, no
  transparency, no rounded corners of your own (`icon.png` as it is).

Generate them when the listing is filled in; they are not committed because
nothing in the build uses them.
